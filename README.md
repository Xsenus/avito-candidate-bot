# Avito → Яндекс Форма → приглашение

Бот опрашивает Avito Messenger, ведёт кандидата по сценарию, нормализует дату и телефон, заполняет Яндекс Форму и только после подтверждённого сохранения ответа отправляет приглашение из Google Таблицы.

## Рабочий сценарий

1. Бот запрашивает последние чаты независимо от отметки «прочитано» и обрабатывает только ещё не сохранённые входящие сообщения. Это исключает пропуск, если менеджер успел открыть чат раньше следующего poll-цикла. Локальные `message_id` и курсоры защищают от повторных ответов.
2. Город и ID объявления берутся из `context.value.location.title` и `context.value.id` чата Avito.
3. Для Москвы, Мытищ, Подольска и Дзержинского бот сразу отправляет два сообщения о вакансии и список восьми московских складов. Для Санкт-Петербурга и Бугров отправляется список из двух петербургских складов.
4. После выбора склада бот собирает день стажировки, фамилию, имя и телефон. Другие города не обслуживаются и не получают сообщения.
5. День недели переводится в ближайшую будущую дату. «Сегодня», «завтра» и явная дата также поддерживаются, а телефон приводится к виду `+7XXXXXXXXXX`.
6. Публичная Яндекс Форма заполняется через Chromium по видимым названиям вопросов. Внутренние ID временной формы не зашиты в код.
7. После появления экрана успешной отправки бот загружает приглашение нужного СЦ из Google Таблицы, подставляет дату и отправляет текст в Avito.
8. Состояния, обработанные сообщения и каждый этап стартовой серии сохраняются в SQLite. После перезапуска бот продолжает с недостающего сообщения, а успешно отправленная форма не создаётся повторно.

### Выбор склада в Москве и Санкт-Петербурге

Согласие на стажировку отдельно не запрашивается. Сразу после нового отклика кандидаты из Москвы, Мытищ, Дзержинского и Подольска получают три сообщения и выбирают один из восьми московских СЦ. Кандидаты из Санкт-Петербурга и Бугров выбирают отображаемые варианты «Троицкий» или «Запад»; второй вариант сохраняется под внутренним названием «Бугры» для Google-таблицы и формы.

Выбор сохраняется в SQLite и имеет приоритет над городом объявления при заполнении формы и поиске приглашения. Ответ `0` завершает диалог со статусом `cancelled`; неправильный номер не переводит кандидата на следующий этап. Все три стартовых сообщения укладываются в лимит Avito 1000 символов.

Финальное приглашение использует дату в формате `ДД.ММ.` и дополняется памяткой о паспорте, смартфоне и контакте с бригадиром. Если памятка уже есть в Google-таблице, она повторно не добавляется. Строка «Остались вопросы?» включается через `INVITATION_INCLUDE_QUESTIONS_LINE=true`.

При первом запуске бот отмечает уже существующую историю как обработанную и начинает отвечать только на последующие новые сообщения. Для незавершённых диалогов текущий этап восстанавливается по последнему известному вопросу бота, но сохранённые ответы повторно не проигрываются. Это исключает повторную рассылку и дубли заявок при переходе со старой версии.

Если соединение оборвалось уже после нажатия «Отправить» и результат невозможно подтвердить, заявка получает статус `uncertain` и не повторяется автоматически, чтобы не создавать дубль.

Постоянные ошибки структуры формы или данных получают статус `configuration_error` и не повторяются автоматически. Временные ошибки повторяются не более `APPLICATION_MAX_RETRIES` раз (по умолчанию 5); после `APPLICATION_ALERT_AFTER_ATTEMPTS` попыток (по умолчанию 3) и при окончательной остановке бот пишет строку `ALERT` в системный журнал. Интервал задаётся `APPLICATION_RETRY_SECONDS` (по умолчанию 300 секунд). Для исчерпанных попыток приглашения используются отдельные статусы, сохраняющие факт уже отправленной формы и исключающие её повторное создание при ручном восстановлении.

### Уведомления об ошибках в Telegram

Журнал `journalctl` ведётся всегда. Для дублирования строк `ALERT` в Telegram задайте:

```env
TELEGRAM_ALERT_BOT_TOKEN=123456:token
TELEGRAM_ALERT_CHAT_ID=-1001234567890
TELEGRAM_ALERT_TIMEOUT_SECONDS=10
```

Без прокси оставьте `TELEGRAM_ALERT_PROXY_URL` пустым. Для HTTP(S) или SOCKS-прокси укажите полный URL; логин и пароль при необходимости включаются в него:

```env
TELEGRAM_ALERT_PROXY_URL=http://user:password@host:port
# или socks5h://user:password@host:port
```

Поддерживаются `http`, `https`, `socks4`, `socks5` и `socks5h`. Ошибка Telegram или прокси только записывается в журнал и не останавливает обработку Avito. Токен не выводится в журнал даже при сетевой ошибке.

Если процесс был остановлен в момент отправки, при следующем запуске состояние `submitting` также переводится в `uncertain` с предупреждением в журнале. Повтор допускается только после ручной проверки ответов формы.

Перед отправкой формы каталог приглашений проверяется: у каждого СЦ должен быть маркер `ДАТА`, не должно быть повторяющихся СЦ, а итоговый текст не должен превышать лимит Avito в 1000 символов. Поэтому испорченная строка таблицы не приведёт к заявке без последующего приглашения.

## Настройка

Скопируйте `.env.example` в `.env` и заполните минимум:

```env
AVITO_CLIENT_ID=...
AVITO_CLIENT_SECRET=...
AVITO_USER_ID=...
YANDEX_FORM_URL=https://forms.yandex.ru/surveys/...
```

Гражданство и тариф по умолчанию: `Российская Федерация` и `Драйв`.

Склад выбирает сам кандидат из списка, поэтому город объявления не назначает конкретный СЦ автоматически. Поддерживаемые группы: Москва/Мытищи/Подольск/Дзержинский и Санкт-Петербург/Бугры. При необходимости соответствие конкретного объявления можно задать через:

```env
SERVICE_CENTER_OVERRIDES_JSON={"8255883375":"Дмитровское","1234567890":"Шушары"}
```

Без такого соответствия бот намеренно не выберет случайный склад и оставит заявку в очереди повторной обработки.

Название приглашения в таблице иногда отличается от варианта формы. Проверенное исключение `Ростов` → `СЦ Ростов-на-Дону` уже встроено. После смены формы дополнительные отличия можно задать отдельно:

```env
FORM_WAREHOUSE_OVERRIDES_JSON={"Название в таблице":"Название в форме"}
```

## Установка на Ubuntu VPS

```bash
chmod +x setup_server.sh
./setup_server.sh
```

Скрипт создаёт виртуальное окружение, устанавливает зависимости и Chromium, затем включает `avito-bot.service`.

Для обновления уже установленного экземпляра используйте транзакционный скрипт:

```bash
DEPLOY_PASSWORD='...' ./deploy_to_ruvds.sh SERVER_IP
```

Он разворачивает код в отдельный release-каталог, сохраняет `.env` и SQLite, запускает тесты и безопасный `preflight.py`, а сервис переключает только после успешных проверок. Если новая версия не стартует, предыдущая автоматически возвращается. Каталог отката сохраняется в `/root/avito_bot_rollbacks/`.

Полезные команды:

```bash
systemctl status avito-bot --no-pager
journalctl -u avito-bot -f
systemctl restart avito-bot
```

## Безопасная смена Яндекс Формы

Ссылка хранится только в `.env`. После получения постоянной формы:

1. измените `YANDEX_FORM_URL`;
2. выполните безопасную проверку заполнения без нажатия «Отправить»:

   ```bash
   python preflight.py
   ```

   Проверка заполняет тестовые поля, нажимает кнопку с блокировкой исходящего POST-запроса и проверяет сформированный JSON без создания ответа. Затем она сверяет варианты складов для всех активных объявлений Avito. При необходимости задайте тестовый склад через `YANDEX_FORM_TEST_WAREHOUSE`;
3. перезапустите сервис;
4. проведите одну контролируемую тестовую заявку.

Если названия вопросов или вариантов изменятся, проверка остановится с явной ошибкой — данные не будут считаться записанными.
